# 메인 프로젝트와 실제 제작 계획

`snowy-applicant/gangwon-water-ai`가 메인이다. 기존 Vercel 화면을 이 사이트에 붙이는 작업이 아니라, 이 저장소의 Python 앱·AI 연구 코드에 하드웨어를 연결한다. 기존 사이트의 DB 자격 증명과 사용자 자료는 가져오지 않는다.

## 실제 배치

사용자가 제시한 두 제작 그림을 기준으로 `hardware/rig.json`에 기록했다.

| 호스 | 수조 → 용기 | 서보 | Uno 신호 핀 | 기존 명령 ID |
|---|---|---|---:|---|
| H1 | A → 지역 1 | M1 | 9 | R1 |
| H2 | A → 지역 3 | M2 | 10 | R3A |
| H3 | B → 지역 3 | M3 | 11 | R3B |
| H4 | B → 지역 2 | M4 | 6 | R2 |

서보는 지지대가 받친 호스의 **끝부분 높이**를 조절한다. 출구를 수면 아래로 내려 공급하고, 최대 수면 위로 올려 차단하는 설계다. 실제 호스 굴곡·내경·출구 높이·서보 회전 방향·유지 토크는 조립 후 확인한다. 스프링 핀치 밸브라는 이전 가정은 사용하지 않는다.

차단 각도에서도 서보 신호를 유지한다. 전원을 끈 뒤 출구가 어디에 머무르는지는 보장하지 않는다. 별도 수동 클램프/호스 들어올리기 등 독립적인 중지 수단과 받침 용량을 확인한다. 외부 전원은 **서보의 정격 전압과 합계 기동/유지 전류에 맞추고** Uno GND와 공통 접지한다. 서보 4개의 전원을 Uno 5V 핀에서 공급하지 않는다.

힘 센서 3개는 지역 1·3·2의 받는 용기에 대응한다. 센서가 용기의 지지/매달림 하중을 실제로 받는 구조여야 한다. 물줄기가 센서에 부딪히는 힘을 용기의 물 무게로 해석하지 않는다. 힘 센서는 PASCO 인터페이스→PC를 통해 읽고, Uno에는 서보를 연결한다. 현재 코드에는 PASCO 전용 통신 드라이버가 없으며 인터페이스 모델·내보내기 형식 확인 후 측정 어댑터를 연결해야 한다.

## v5 펌웨어와 기존 코드의 차이

- 기존 `resilient-water-ai` v4 펌웨어에서 명령 형식·핀 배치·시작 잠금·5초 heartbeat 제한·STOP 래치를 가져왔다. v5는 높이 조절 장치다.
- EEPROM 버전을 바꿔 이전 핀치 밸브의 공급/차단 각도를 재사용하지 않는다.
- 초기 상태는 각도 미보정이다. 미보정 서보는 부팅 시 움직이지 않고 `OPENM`과 `POS`를 거절한다.
- `ANG <명령 ID> <공급 각도> <차단 각도>`를 현장에서 지정한다. 저장 즉시 차단 각도로 움직이므로 **물을 넣기 전** 기구 범위와 각도를 확인한다. 보정 플래그는 입력된 각도의 존재를 뜻하며 실제 차단 검증 결과가 아니다.
- 공급 시간은 200~65,000 ms(기본)다. `OPENM` 순서는 H1/H2/H3/H4이며 실제 공급량은 시간과 동일하지 않다.
- `ST ... L=...`은 명령 상태다. 위치 피드백·실제 차단·측정 유량을 뜻하지 않는다. `DONE` 시간 역시 명령을 유지한 시간이다.

## PC 연결 순서

저장소 루트에서 실행한다. Python 서버는 `.env`를 자동으로 읽지 않으므로 환경변수를 직접 설정한다.

1. `python -m venv .venv` 후 가상환경을 활성화하고 `pip install -r requirements.txt`를 실행한다. USB 시리얼에는 추가로 `pip install -r hardware/requirements.txt`가 필요하다.
2. 서로 다른 관리자·장치 토큰을 각각 생성한다. `python -c 'import secrets; print(secrets.token_urlsafe(32))'`를 두 번 실행하고 `WATERAI_ADMIN_TOKEN`, `WATERAI_SENSOR_TOKEN` 환경변수로 설정한다. 토큰을 Git에 저장하지 않는다.
3. 웹 전체 계산 화면을 실행하려면 `python -m waterai.runtime`, `python -m waterai.build`를 한 번 실행한다. `python -m waterai.server`로 수신 서버를 시작한다. 다른 PC에서 접근하려면 HTTPS 서버와 영구 DB 볼륨을 구성한다. 정적 사이트 주소는 센서 수신 서버가 아니다.
4. Arduino IDE에서 `hardware/firmware/water_rig/water_rig.ino`를 Uno에 업로드한다. 실제 포트명은 연결한 PC에서 확인한다.
5. 우선 읽기 전용 상태 확인으로 연결한다. 아래 포트명은 예시다.

   ```sh
   python hardware/bridge.py --url http://127.0.0.1:8000 --device-id uno-1 --port /dev/cu.usbmodemXXXX
   ```

   기본 통신 속도는 펌웨어와 같은 38400 baud다. 이 모드는 명령·heartbeat를 보내지 않는다. USB 포트를 열면 Uno가 재부팅될 수 있다.

6. 현장에서 보정·수동 제어할 때만 `--allow-control`을 추가한다. 브리지는 1초 간격 heartbeat를 보내지만 자동으로 ARM하거나 공급 명령을 만들지 않는다. 연결 후 부팅 줄 또는 `PING`의 최신 번호를 읽고 `ARM 번호`를 직접 입력한다. `ANG`/`POS`로 물 없이 기구를 확인한 뒤 짧은 시간부터 공급 시험한다. `STOP`은 차단 각도 이동·잠금, `QUIT`/Ctrl-C는 종료 시 STOP 전송을 시도한다. STOP 송신 실패·전원 상실 때에는 독립적인 수동 차단을 사용한다.
7. 웹의 **AI 모델 · 데이터 → Python 서버 관리자 연결**에서 관리자 토큰을 입력한 뒤 **하드웨어 · 실측** 탭을 연다. Uno 상태는 약 1초 간격으로 업로드하고 화면은 활성 탭에서 3초마다 조회한다. 마지막 실제 관측이 5초 넘게 오래되면 표시하며 `0`으로 바꾸지 않는다.

네트워크 업로드는 별도 스레드에서 실행되어 로컬 heartbeat/STOP를 막지 않는다. 연결 실패 시 해당 상태 표본이 유실될 수 있다. 이 브리지는 실험 원본 로거를 대신하지 않으며 학습 실험의 원본 파일은 측정 소프트웨어에서도 보관한다.

## PASCO 측정 어댑터 계약

인터페이스에서 읽은 **실제 측정값**을 다음 JSONL 형식으로 PC 어댑터가 출력하면 `bridge.py`가 전달한다. 아래는 형식 설명이며 실제 관측 자료가 아니다. `F1`=지역1, `F3`=지역3, `F2`=지역2다.

```json
{"kind":"measurement","channel_id":"F1","values":{"force_n":0.0}}
```

```sh
python your_pasco_reader.py | python hardware/bridge.py --url http://127.0.0.1:8000 --device-id pasco-1
```

`your_pasco_reader.py`는 아직 없는 어댑터의 자리표시자다. 이것을 실행 가능한 PASCO 드라이버라고 해석하지 않는다. 저장된 실험을 다시 보낼 때는 `sample_id`, 원래 시간대가 포함된 `observed_at`을 넣어 수집 시각을 보존한다. 생략하면 브리지가 읽은 시각을 부여하므로 실시간 어댑터에만 적합하다. 실패한 표본의 자동 재전송은 하지 않으며, 같은 ID·내용을 다시 보내면 중복 저장하지 않는다.

장치 인증 쓰기 API는 `POST /api/hardware`, 관리자 조회는 `GET /api/hardware`, 원시 자료 내보내기는 `GET /api/hardware/export`다. 내보내기는 최신 10,000개와 전체 개수를 제공한다. 10,000개를 넘는 학습 자료는 SQLite 원본/실험 로거 파일을 이용한다. SQLite는 영구 저장소에 둔다. 장치 상태와 측정은 종류·채널·원래 관측 시각·수신 시각을 구분한다. 탁상 실측을 기존 강원도 `demo_network()`에 자동 대입하지 않는다.

## PINN에 사용할 수 있는 관측과 부족한 정보

하드웨어용 핵심 모델은 새 `waterai/rig_pinn.py`다. 수조·호스 그래프의 시간별 누적 공급량과 유량을 실제로 학습하고 신경망 예측 API를 제공한다. 현재는 합성 치수로 사전 학습했으며 실측 학습을 완료한 것은 아니다. 기존 `waterai/pinn.py`는 단일 압력 관로 비교 벤치마크로 남긴다. [새 PINN의 구조·검증·실측 보정과 재학습](RIG_PINN.md)을 확인한다.

용기의 지지 하중을 측정하는 배치에서 영점 `F0`와 센서 방향 `s=±1`을 보정하면 다음 관계로 물의 체적을 추정할 수 있다.

```text
V = s × (F − F0) / (ρg)
q_receiver ≈ dV/dt
```

`force_to_volume`과 `volume_rate`는 이 보정 계산을 위한 함수다. 원본 힘(N)을 덮어쓰지 않으며 유량을 압력으로 해석하지 않는다. 밀도 기본값 1,000 kg/m³와 g=9.80665 m/s²는 명시적 근사다. 용기를 만지거나 비우는 구간, 진동·물줄기 충격·영점 변동은 분리해야 한다. 원시 API는 이 보정을 자동 실행하지 않는다.

향후 실험 PINN에서 제약으로 사용할 물수지는 다음과 같다. 수조 보충이 없을 때 수조 A/B의 체적 감소는 각각 두 호스 유출량의 합과 같고, 받는 용기 3의 체적 증가는 H2/H3 유량의 합과 같다. 물수지만으로 호스별 유량과 저항을 모두 식별할 수 있는 것은 아니다.

```text
dVA/dt = −qH1 − qH2           dVB/dt = −qH3 − qH4
dVR1/dt = qH1                dVR3/dt = qH2 + qH3
dVR2/dt = qH4
```

필요한 추가 자료는 실제 수조 단면적·초기 물량·수면 높이, 호스 길이/내경, 시간별 출구 높이와 서보 각도의 보정표, 보충·배수 이력이다. 이 값은 아직 없으므로 `rig.json`에 임의로 채우지 않았다. 실제 각도/높이 센서가 없으면 명령 각도를 실측 높이로 주장할 수 없다.

특히 F3 하나로 H2/H3 동시 유입의 각 유량을 독립적으로 검증할 수 없다. H2만 공급, H3만 공급하는 개별 보정 실험 후 동시 공급을 시험한다. 여러 수위·출구 높이 조건 중 일부를 학습에서 제외해 검증해야 한다. 탁상 실험 검증을 강원도 실제 관망의 정확도로 주장하지 않는다.

## 검증 범위

`python -m unittest discover -s tests -v`는 API 인증·중복·시각·단위, 힘/체적 환산, 브리지 명령 및 실제 펌웨어의 시작 잠금·미보정 거절·타이머·heartbeat·STOP 동작을 검사한다. 펌웨어 검사는 g++로 시계·핀을 모사해 실행하며 실제 유량·물리적 차단을 가정하는 가짜 수리 모델은 사용하지 않는다. g++가 없으면 이 검사는 건너뛴다. AVR 보드 빌드와 실물 시험은 Arduino 도구/장치로 별도 확인해야 한다.
